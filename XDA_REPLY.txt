[SIZE=4][B]Update: LSPosed/Vector "SEPolicy is not loaded properly" fix on Magisk 31.1[/B][/SIZE]

If you installed LSPosed or Vector on Magisk 31.1 and see [B]"Partially activated"[/B] + [B]"SEPolicy is not loaded properly"[/B], this is a known issue: Magisk 31.1 (Rust rewrite) does [B]not[/B] apply module `sepolicy.rule` files at boot. The `/data/.magisk/preinit/sepolicy.rule` file that magiskinit reads doesn't even get created.

[B]Symptoms:[/B]
[LIST]
[*]Manager shows "Partially activated" / "SEPolicy is not loaded properly"
[*]logcat shows [CODE]Failed to execute (...dex2oat...): Permission denied[/CODE]
[*]Manager APK fails to install (dex2oat EACCES)
[*]Module detection cache write fails (EACCES)
[/LIST]

[B]Fix (no reboot required):[/B]
[CODE]
# 1. Apply the rules live now
adb shell 'su -c "magiskpolicy --live --apply /data/adb/modules/zygisk_lsposed/sepolicy.rule"'
# (or zygisk_vector/sepolicy.rule if using Vector)

# 2. Persist across reboots (Magisk 31.1 won't do this automatically)
adb shell 'su -c "cat > /data/adb/service.d/99_lsposed_sepolicy.sh <<EOF
#!/system/bin/sh
magiskpolicy --live --apply /data/adb/modules/zygisk_lsposed/sepolicy.rule
EOF
chmod 755 /data/adb/service.d/99_lsposed_sepolicy.sh"'
[/CODE]

After step 1, the notification changes from "Partially activated" to "Vector/LSPosed loaded" and the manager APK installs successfully.

[B]Notes:[/B]
[LIST]
[*]`magiskpolicy --live` only changes runtime policy — does not modify on-disk compiled policy. Reboot without the script reverts to stock SELinux (safer).
[*]The service.d script re-applies at every boot. Remove it if you uninstall the module.
[*]These are the standard Xposed sepolicy rules — same as what LSPosed applies on a compatible Magisk. No new rules beyond what the module ships.
[*]Downside: these rules relax SELinux (necessary for Xposed). If you don't need Xposed, uninstall the module to restore full enforcement.
[/LIST]

[B]Root cause detail:[/B] Magisk's init code reads `/data/.magisk/preinit/sepolicy.rule` at boot. In Magisk 31.1, module `sepolicy.rule` files are never concatenated into this file (regression vs older Magisk). The rules exist in the module directory but are never loaded.

Tested on SM-T220 / Android 14 / T220XXSAEYE4 with Magisk 31.1 + Vector 2.2 (JingMatrix fork).
